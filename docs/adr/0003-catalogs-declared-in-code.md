# Catalogs are declared in code by the theme or plugin that owns them

From 3.0.0 a product catalog is declared by the theme or plugin that registers its content type, with `thatseoagent_register_catalog()` on the `thatseoagent_init` hook, and no longer chosen and mapped under Settings → Product catalogs. The screen guessed which taxonomies and meta keys held the brand, the specifications or the gallery, and a site owner had to confirm a mapping they could not judge; the code that registers the type knows where its data lives, and can hand over values no meta key holds, through a callback. ThatSeoAgent keeps everything that follows from a declaration: the validated Product markup, `/catalog.jsonl`, the catalog in llms.txt, the Products screen, the bulletin and `wp thatseoagent validate-products`.

The cost is that a site whose theme declares nothing has no catalog, and a site owner cannot make one from the screen. That is accepted: the declaration is public API, documented for the themes and plugins that list products. WooCommerce's product types cannot be declared while WooCommerce is active, since WooCommerce marks them up itself; declaring one is ignored with `_doing_it_wrong()`. The `thatseoagent_products` option of earlier versions is deleted on upgrade, with no migration: only one site used it, and its theme declares its catalog in the same release.
